fdo-squirrel-md-generator FDOx-squirrel Erzeugt MD.cff und CITATION.cff fuer ein FDO-Paket. Rolle nur aus dem Repo-Namen erschlossen, nicht am echten Code verifiziert (siehe PRIMER.md Teil D). MD.cff, CITATION.cff (YAML) —
fdo-squirrel FDOx-squirrel FDOx-Referenzimplementierung: liest ein FDO-Paket (ZIP), schreibt fdo-metadata.ttl. v0.1, publiziert (Zenodo DOI 10.5281/zenodo.18441772) fdo-metadata.ttl (RDF/Turtle); rdf_modelling_report.json / .html (JSON/HTML) aus fdo-squirrel-md-generator: MD.cff, CITATION.cff (YAML); extern: FDO-Paket (ZIP) (Modell-/Datendateien + Metadaten)
fdo-squirrel-spec FDOx-squirrel Dokumentation: rendert eine ReSpec-Seite aus Kopien von Schema, RDF-Crosswalk und Klassifikationsregeln aus fdo-squirrel. Publiziert selbst kein neues RDF. S1 gebaut (2026-09-03), docs/index.html rendert offline docs/index.html (HTML (ReSpec)) aus fdo-squirrel: MD.cff-schema.yaml, crosswalk_md_cff_to_rdf.yaml, classification_rules.yaml, package_source.py (YAML/Python)
fdo-squirrel-registry FDOx-squirrel Erntet auf Zenodo publizierte FDOx-Pakete, buendelt ihre RDF-Beschreibungen zu einem DCAT-Katalog, verankert an CIDOC CRM (N4O-Anwendungsprofil crm-rdf-ap) und SHACL-validiert das Ergebnis, liefert Facetten- und SPARQL-Seite ueber GitHub Pages. S0-S9 fertig (Stand 2026-09-04), inkl. eigenem FDO-Release (S8) und N4O-Andockung (S9, siehe fdox-squirrel-n4o-collection). S10 laeuft: Restarbeiten, u.a. der Zenodo-Publish des eigenen Release-Bundles. dist/fdo-registry.ttl (RDF/Turtle); dist/fdo-registry-n4o.ttl (RDF/Turtle); dist/registry-index.json (JSON) aus fdo-squirrel: fdo-metadata.ttl (von Zenodo geernteter Pakete) (RDF/Turtle)
fdox-squirrel-n4o-collection FDOx-squirrel Collection-Repo fuer den NFDI4Objects Knowledge Graph: haelt nur metadata.yaml, laesst n4o-kg-profile daraus Registrierungssatz, VoID-Statistik, CRM-Alignment und eine Browser-SPARQL-Seite bauen. Live seit 2026-09-04. Build und Pages-Deploy gruen, push-Trigger aktiv. metadata.yaml/id und /homepage zeigen noch auf die GitHub-URL der Registry statt einer echten DOI (haengt am Zenodo-Publish von fdo-squirrel-registry S8, siehe dort S10). dist/n4o-collection.ttl, dist/metadata.ttl (RDF/Turtle, JSON-LD) aus fdo-squirrel-registry: dist/fdo-registry-n4o.ttl (RDF/Turtle); aus n4o-kg-profile: profile/, build/ (SHACL-Gate, Metadaten-/Seiten-Generatoren) (Python/Turtle/SHACL)
n4o-kg-profile n4o-rse Projektuebergreifendes Werkzeug (nicht Teil der FDOx-Familie, gehoert aber ebenfalls Flo): baut aus einer metadata.yaml Metadaten-RDF, CIDOC-CRM-Alignment und eine Browser-SPARQL-Seite fuer eine NFDI4Objects-KG-Collection. In Benutzung durch fdox-squirrel-n4o-collection, drei Bugs am 2026-09-04 direkt gepatcht und in echtem CI verifiziert (kein v1-Tag; Checkout auf einen 404-Org-Pfad; Selbst-Checkout via github.action_ref loeste auf den falschen Ref auf, behoben durch github.action_path).
